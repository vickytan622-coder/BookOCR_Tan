## 它能做什么

```text
扫描 PDF
→ 本地 300 DPI 图像渲染
→ PaddleOCR-VL 识别（可选 Apple 芯片 MLX 加速）
→ 失败页自动 CPU 兼容重试
→ 原始 Markdown
→ 自动质量检查
→ 用户自选 LLM 保守校对
→ 最终 Markdown
```

核心能力：

- **按页断点**：几百页的书中断后可以继续，不需要从头开始；
- **本机优先**：PDF 不上传，模型本地运行，API Key 存 macOS 钥匙串；
- **Apple 加速**：M 系列芯片可用 MLX 本地服务加速；失败页自动回退 CPU；
- **不锁定厂商**：只要兼容 OpenAI Chat Completions 格式，DeepSeek、Kimi、GPT 等都可以；
- **原始结果永存**：OCR 原稿和 LLM 校对稿分开保存，改错了也能回退。

## 系统要求

- **芯片**：Apple Silicon（M1 / M2 / M3 / M4 系列）
- **系统**：macOS 13 或更高版本（建议最新版）
- **Python**：3.11 或 3.12（安装脚本会自动检测）
- **磁盘**：至少预留 10 GB 空间（模型缓存 + 输出文件）
- **内存**：建议 16 GB 及以上；大页 PDF 会占用更多内存

> 当前试用版**不支持 Intel Mac 和 Windows**。后续可能扩展，但现在请不要在 Windows 上尝试安装。

## 隐私说明

- PDF 文件、渲染出的页面图、OCR 结果、Markdown 输出全部保存在你指定的本机目录；
- 调用 LLM 时，只有**已经识别出的 Markdown 文本**会发送到你配置的模型服务，原 PDF 图片不会上传；
- API Key 第一次保存后写入 macOS 钥匙串（Keychain），**不会写入任何项目文件、数据库或 Git 仓库**；
- Base URL 和模型名保存在 `~/Library/Application Support/BookOCR/settings.json`；
- 本地 Web 服务只监听 `127.0.0.1`，局域网内的其他设备无法访问。

## 费用提醒

- **OCR 阶段**：使用本地模型，不产生供应商 API 费用；
- **LLM 校对阶段**：按页请求模型服务，会产生你配置的供应商的费用，费用由供应商决定；
- 首次使用 LLM 校对建议先填“先校对前几页”（例如 3 页），确认效果和费用后再跑全书；
- 开启“OCR 全部完成后自动开始校对”前，请确认已保存正确的模型配置。

## 安装

1. 从 GitHub 下载或克隆本仓库到本地文件夹。
2. 在 Finder 中进入项目文件夹。
3. **双击** `安装 BookOCR.command`。

脚本会：

- 检测本机 Python 版本（必须是 3.11 或 3.12）；
- 创建项目内的 `.venv` 虚拟环境；
- 安装 Python 包依赖、PaddleOCR、Web UI 和 MLX 加速包；
- 运行一次 `bookocr doctor` 检查环境。

安装完成后会弹出提示，按任意键关闭窗口即可。

> 如果系统提示“无法打开，因为无法验证开发者”，请前往 **系统设置 → 隐私与安全性 → 安全性**，点击“仍要打开”。

## 第一次使用（推荐先跑 1 页）

第一次使用不要直接跑整本书，先跑 1 页让模型下载并热身：

1. 双击 `启动 BookOCR.command`，浏览器会自动打开 `http://127.0.0.1:8765`；
2. 点击 **浏览 PDF…**，选择一本扫描 PDF；
3. 点击 **选择输出目录…**，选择要保存结果的位置；
4. 点击 **创建任务**；
5. 在“本次 OCR 页数”里填 `1`；
6. **不要勾选**“使用本机 Apple 芯片加速”；
7. 点击 **开始识别**。

首次会下载 PaddleOCR 模型，可能需要几分钟到十几分钟，取决于网络。耐心等待，不要关闭终端窗口。

1 页完成后，你会看到“OCR 已完成：1/1 页”。

## 完整工作流程

### 1. 启动 Apple 芯片加速（可选但推荐）

1 页试跑成功后：

1. 点击网页里的 **启动 Apple 加速**；
2. 会弹出一个新的终端窗口，正在启动 MLX 服务；
3. 等待终端显示服务已就绪（通常会显示监听 `127.0.0.1:8118`）；
4. 网页会自动勾选“使用本机 Apple 芯片加速”。

> 必须保持 MLX 终端窗口打开；关闭它会导致加速停止，但已成功的页面不会丢失。

### 2. 识别整本书

1. 清空“本次 OCR 页数”（留空表示全部）；
2. 确认“使用本机 Apple 芯片加速”已勾选；
3. 点击 **开始识别剩余页面**；
4. 进度条和状态文字会自动更新；
5. 如果少数页面因形状兼容问题失败，程序会自动进入“兼容重试进度”，用 CPU 只重试失败页；
6. 全部完成后按钮会变回可用状态。

### 3. 生成原始 Markdown

1. 点击 **生成原始 Markdown**；
2. 等待按钮旁显示 “✓ 已生成：…”，文件名会显示出来；
3. 原始 Markdown 保存在任务输出文件夹中，文件名为 `<书名>.raw.md`。

### 4. 运行质量检查

1. 点击 **运行质量检查**；
2. 按钮旁会显示 “✓ 检查完成：N/N 页齐全”；
3. 如果有页面被标记为需要复核，会显示建议复核的页数；
4. 详细结果保存在同目录下的 `qa_report.json`。

> 质量检查只能发现“缺页”“文字过短”等规则问题，不代表文字 100% 正确。建议人工抽查几页。

### 5. 配置 LLM 并校对

1. 在“LLM 保守校对”区域填写：
   - **Base URL**：例如 `https://api.deepseek.com`；
   - **模型名**：例如 `deepseek-v4-pro`；
   - **API Key**：你的 API Key。
2. 点击 **保存模型配置**；
3. 首次建议先在“先校对前几页”填 `3`，点击 **立即开始校对**；
4. 查看效果、检查费用；
5. 满意后清空“先校对前几页”，点击 **继续校对** 跑完整本书。

校对过程中：

- 页面进度会自动刷新；
- 网络波动时会显示“网络波动，等待 N 秒后自动重试”；
- 可随时点击 **暂停校对**，之后点击 **继续校对** 从断点恢复；
- 完成后会显示 “✓ 校对完成：N/N 页”。

## 界面分区说明

### 创建 / 继续 OCR

| 控件 | 作用 |
| --- | --- |
| 浏览 PDF… | 用 macOS 文件选择器选扫描 PDF |
| 选择输出目录… | 选结果保存位置 |
| 创建任务 | 生成任务 ID 并记录 PDF 页数 |
| 使用本机 Apple 芯片加速 | 勾选后调用 MLX 本地服务 |
| 启动 Apple 加速 | 打开 MLX 服务终端窗口 |
| 本次 OCR 页数 | 首次建议填 1；留空=全部 |
| 开始识别 / 继续识别剩余页面 | 启动 OCR 工作线程 |
| 查看进度 | 手动刷新当前任务状态 |

### 导出与质量检查

| 控件 | 作用 |
| --- | --- |
| 生成原始 Markdown | 汇总所有页面为 `<书名>.raw.md` |
| 运行质量检查 | 检查缺页、文字过短等异常 |

### LLM 保守校对

| 控件 | 作用 |
| --- | --- |
| Base URL | 你的 OpenAI 兼容服务地址 |
| 模型名 | 服务商提供的模型名 |
| API Key | 首次保存后存入钥匙串 |
| OCR 全部完成后自动开始校对 | 自动化开关 |
| 保存模型配置 | 保存 URL/模型名/Key |
| 先校对前几页 | 空白=全书；填数字=只校前 N 页 |
| 立即开始校对 | 启动校对 |
| 暂停校对 / 继续校对 | 人工中断和恢复 |
| 刷新校对状态 | 手动刷新进度 |
| 停止 BookOCR 服务 | 安全关闭本地 Web 服务 |

## 命令行参考

除了网页，也可以用终端执行：

```bash
# 检查环境
.venv/bin/bookocr doctor

# 创建任务
.venv/bin/bookocr create-job /path/to/book.pdf --output output/jobs

# 查看任务状态
.venv/bin/bookocr status <任务ID>

# 运行 OCR（可限定页数试跑）
.venv/bin/bookocr run-ocr <任务ID> --max-pages 3

# 使用 MLX 本地加速
.venv/bin/bookocr run-ocr <任务ID> --vl-backend mlx-vlm-server \
  --vl-server-url http://127.0.0.1:8118/v1

# 生成原始 Markdown
.venv/bin/bookocr assemble <任务ID>

# 质量检查
.venv/bin/bookocr audit <任务ID>

# 使用已保存配置校对
.venv/bin/bookocr proofread <任务ID>

# 启动本地 Web 服务
.venv/bin/bookocr serve --port 8765
```

## 输出文件说明

每个任务会在输出目录下创建一个独立子文件夹 `<书名>-<任务ID>/`：

```text
<所选输出目录>/
└── <书名>-<任务ID>/
    ├── rendered/                  # 300 DPI 页面图（OCR 输入）
    ├── pages/page_000001/         # 每页 OCR 原始结果
    ├── restructured/              # Paddle 文档重组结果
    ├── proofread_pages/           # LLM 校对逐页断点
    ├── proofread_progress.json    # 校对进度状态
    ├── <书名>.raw.md              # 原始整书 Markdown
    ├── qa_report.json             # 质量检查报告
    └── <书名>.proofread.md        # 最终校对稿
```

- `*.raw.md`：OCR 直接结果，永远保留；
- `*.proofread.md`：LLM 校对后的最终稿；
- `proofread_pages/`：每页独立断点文件，中断后可跳过已完成的页；
- `qa_report.json`：记录建议人工复核的页面。

## 常见问题

**Q：双击安装脚本后提示“需要 Python 3.11 或 3.12”怎么办？**

A：从 python.org 或 Homebrew 安装 Python 3.11 或 3.12，然后重新运行安装脚本。

**Q：启动后浏览器没有自动打开？**

A：手动访问 `http://127.0.0.1:8765`。如果打不开，查看启动脚本所在终端窗口是否有错误信息。

**Q：端口 8765 被占用？**

A：如果占用进程是 BookOCR，脚本会直接打开浏览器；如果是其他程序，先关闭那个程序再启动。

**Q：MLX 加速服务启动很慢？**

A：首次启动会下载/加载模型，可能需要几分钟；保持终端窗口打开，等待显示“服务已就绪”。

**Q：校对应网络波动时等了很久？**

A：程序会自动指数退避重试（5/15/30/60/120 秒，最长 5 分钟）。如果长时间没恢复，可以点击 **暂停校对**，检查网络后再 **继续校对**。

**Q：API Key 填错了怎么改？**

A：重新在网页里填写并点击 **保存模型配置**，新 Key 会覆盖钥匙串里的旧 Key。

**Q：任务中断后怎么恢复？**

A：重新双击 `启动 BookOCR.command`，网页会自动加载最近一次任务 ID；点击 **查看进度**，然后点击 **继续识别剩余页面** 或 **继续校对**。

**Q：可以关闭电脑盖子吗？**

A：Mac 睡眠会暂停本地服务。建议长任务运行时插上电源，并在终端里运行 `caffeinate -d` 阻止睡眠；或者分多次手动继续。

## 已知限制

- 当前仅支持 Apple Silicon Mac，不支持 Intel Mac 和 Windows；
- 表格会被 PaddleOCR-VL 输出为 HTML 表格标签，不会自动转换为 Markdown 表格；
- 质量检查只能发现缺页、文字过短等规则问题，不能判断语义正确性；
- LLM 校对会消耗 API 额度，且取决于模型服务质量；
- 长任务运行时若 Mac 睡眠，服务会暂停，需要手动继续；
- 非常复杂的版式（如多栏混排、手写批注）识别效果可能不稳定。
